# GitHub Settings Audit — 2026-08-08

Recorded to satisfy [Issue #21](https://github.com/kgsmith19/prompt-organizer/issues/21) acceptance criteria: "the actual (not assumed) state of branch protection and labels is recorded somewhere durable."

---

## 1. Branch-protection / ruleset

**Inspection method:** GitHub MCP `list_branches` + manual inspection of Settings → Branches (noted by the originating session's read-only audit on 2026-08-08).

**Findings:** No branch-protection ruleset or classic branch-protection rule was found for `main` at time of audit. The CI workflow (`ci.yml`) acts as a soft gate (required check `PR Gate`) but no ruleset enforces it at the GitHub layer. Closing the gap — creating the ruleset — requires admin access that the current tooling does not expose. This remains an open item; a human with admin rights should create the `main` ruleset matching the `agent-engineering-standard` bootstrap expectation (require PR, require status check `PR Gate`, require linear history).

## 2. Label taxonomy

**Pre-existing labels (found in repo):**

| Label | Status |
|---|---|
| `bug`, `documentation`, `duplicate`, `enhancement`, `good first issue`, `help wanted`, `invalid`, `question`, `wontfix` | GitHub defaults — not part of portfolio taxonomy |
| `risk:R0` through `risk:R4` | ✅ Present |
| `status:ready`, `status:blocked` | ✅ Present |
| `status:in-progress` | ❌ Missing |

**Missing from full portfolio taxonomy:**

`type:feature`, `type:bug`, `type:chore`, `type:docs`, `type:refactor`,
`agent:human`, `agent:copilot`,
`priority:p0`, `priority:p1`, `priority:p2`,
`automerge:squash`, `automerge:merge`,
`ci:full`, `release:requested`,
`status:in-progress`

**Remediation:** `.github/workflows/apply-labels.yml` (added in the same commit as this file) is a manually-dispatchable workflow that idempotently creates or updates the full taxonomy. Run it once via Actions → "Apply Label Taxonomy" → "Run workflow" to close this gap.

## 3. Follow-up: `supabase/migrations/**` → R3+ label CI gate

Surfaced by the same audit: no mechanical CI check verifies that a PR touching `supabase/migrations/**` carries a `risk:R3` or `risk:R4` label before merge. Risk classification is self-declared only.

A lightweight path-based gate could be added to `ci.yml` using a label check step. This is tracked as a separate concern; see Issue #21 closing comment or open a new issue when capacity allows.
